## Q1. 指针表达式分析

**难度：简单**　**标签：指针、地址、解引用**　**答题文件：`q01.c`**

### 题目描述

给定以下 C 代码，请分析对象的值、指针指向和表达式的合法性，并解释原因。

```c
uint16_t adc[4] = {100u, 200u, 300u, 400u};
uint16_t *p = &adc[1];
uint16_t *end = adc + 4;
uint16_t copy = *p;
*p = 250u;
++p;
```

规定两个观察时刻：

- **T0**：执行完 `uint16_t copy = *p;`，尚未执行 `*p = 250u;`。
- **T1**：上述六条语句全部执行完毕。

请在 `q01.c` 注释中逐项回答：

1. 分别在 T0、T1 说明 `adc[1]`、`&adc[1]`、`p`、`&p`、`*p` 的类型、含义，以及表示的值或地址。地址描述为“哪个对象的地址”即可。
2. T1 时 `copy`、数组四个元素、`*p` 各是什么值？普通整数赋值是否会让副本随原对象一起变化？
3. T1 时 `p - adc`、`end - adc` 的结果及类型是什么？`p + 1` 偏移多少个元素，字节数如何用 `sizeof` 表达？
4. 在 T1，分别判断 `adc + 4`、`*(adc + 4)`、`adc + 5`、`p[-1]`、`adc - 1`、`end == adc + 4` 求值是否合法。区分“形成指针”与“解引用”。
5. 另有独立数组 `uint16_t other[4]`，为什么不能用 `p < other` 或 `p - other` 判断它与 `adc` 的相对位置？

### 提示与约束

- 这是分析题，不要求实现业务函数；在注释中给出结论和原因，在 `main()` 中验证合法表达式。
- 不要实际执行非法解引用或越界指针运算来“验证”。
- 打印地址使用 `%p`，对应参数转为 `(void *)`；指针差值使用 `ptrdiff_t` 和 `%td`。
- 不要求固定的绝对地址，不假定宿主机指针与 STM32 指针一样宽。

## Q3. 生成 ADC 采样序列

**难度：中等**　**标签：指针、数组、边界处理**　**答题文件：`q03.c`**

### 题目描述

给定目标数组 `dst`、要生成的数量 `count`、首个数值 `start` 和数值步长 `step`，将生成的序列写入 `dst` 的前 `count` 个元素。

第 `i` 个生成值的数学表达式为：

```text
a[i] = start + i × step，0 ≤ i < count
```

所有生成值必须在 `[0,4095]` 内。全部合法时写入序列并返回 `0`；只要一个值越界，就返回 `-2`，并保证整个目标数组保持调用前状态。

`count == 0` 表示空操作，直接按成功处理，允许 `dst == NULL`，忽略 `start` 和 `step`。`count > 0` 且 `dst == NULL` 时返回 `-1`。

### 函数签名

```c
int fill_adc_samples(uint16_t *dst, size_t count,
                     uint16_t start, uint16_t step);
```

参数顺序为 `dst, count, start, step`。`count` 是元素数量，`start` 是首个生成值，`step` 是相邻生成值的差；三者都不表示指针的字节偏移。

### 示例 1

```text
输入：dst = [777,777,777,777], count = 4, start = 100, step = 25
输出：返回值 = 0, dst = [100,125,150,175]
解释：生成 4 个元素，从 100 开始，相邻两个值相差 25。
```

### 示例 2

```text
输入：dst = [777,777,777,777], count = 3, start = 4090, step = 10
输出：返回值 = -2, dst = [777,777,777,777]
解释：第二个生成值为 4100，超过 4095，所以整个数组都不能更新。
```

### 示例 3

```text
输入：dst = NULL, count = 0, start = 65535, step = 65535
输出：返回值 = 0
解释：没有需要生成的元素，因此不访问 dst，也不检查 start 和 step。
```

### 示例 4

```text
输入：dst = [777,777,777,777], count = 1, start = 100, step = 65535
输出：返回值 = 0, dst = [100,777,777,777]
解释：只生成第 0 个元素 start，不生成下一项，因此 step 不影响结果。
```

### 提示与约束

- `count` 的类型为 `size_t`，单位是元素；`start`、`step` 的类型为 `uint16_t`，均可表示 0～65535。
- 判定优先级：`count == 0` → 返回 `0`；否则若 dst 为 NULL → 返回 `-1`；否则检查所有数学生成值，越界返回 `-2`，全部合法返回 `0`。
- `count > 0` 时，调用者保证 dst 指向至少 count 个可写元素；接口没有独立容量参数，函数不负责推测实际数组大小。
- 单元素指 `count == 1`，与 start 是否等于 1 无关；此时 start 仍须在 `[0,4095]` 内。
- `step == 0` 合法：非空时重复生成 start；如果 start 越界仍应失败。
- 成功只修改前 count 个元素，其余元素保持不变；失败时目标数组一个元素也不能改变。
- 范围以数学结果为准，不能把截断后的值当作合法结果。例如 `100+65535=65635`，不能将其截断为 99 后继续写入。乘法、加法、循环计数本身也不能溢出或回绕。
- 通过指针解引用写入，例如 `*p` 或 `*(dst+i)`；不要用 `dst[i]` 写入。自测读取结果时可以用数组下标。
- 空操作不能解引用 NULL，也不能对 NULL 做指针运算。

### 补充测试

每行独立初始化 `uint16_t buf[4] = {777,777,777,777};`。表中“原样”表示四个元素仍全为 777。

| dst  | count | start | step  | 预期返回值 | 调用后的 buf              |
| ---- | ----- | ----- | ----- | ----- | --------------------- |
| buf  | 0     | 65535 | 65535 | `0`   | 原样                    |
| NULL | 2     | 65535 | 65535 | `-1`  | 不访问数组                 |
| buf  | 2     | 1     | 3     | `0`   | `{1,4,777,777}`       |
| buf  | 3     | 100   | 0     | `0`   | `{100,100,100,777}`   |
| buf  | 1     | 4095  | 0     | `0`   | `{4095,777,777,777}`  |
| buf  | 2     | 4090  | 5     | `0`   | `{4090,4095,777,777}` |
| buf  | 1     | 4096  | 0     | `-2`  | 原样                    |
| buf  | 2     | 100   | 65535 | `-2`  | 原样                    |
| buf  | 2     | 65535 | 1     | `-2`  | 原样                    |

再将目标范围放在两个哨兵值之间，确认成功、失败都没有额外写入。

## Q4. 指针区间求和

**难度：中等**　**标签：尾后指针、只读指针、整数溢出**　**答题文件：`q04.c`**

### 题目描述

给定起始指针 `begin`、停止指针 `end` 和输出指针 `out_sum`，计算区间 `[begin,end)` 内所有元素的和，通过 `out_sum` 输出。

区间包含 begin，不包含 end。例如 begin=`a+1`、end=`a+3`，只累加 a[1]、a[2]。输入元素允许为完整 `uint16_t` 范围，不额外限制为 12 位 ADC 值。

成功返回 `0`；输出指针或区间参数非法返回 `-1`；数学总和超过 `UINT32_MAX` 返回 `-2`。失败时输出保留原值，输入数组始终不变。

### 函数签名

```c
int sum_adc_range(const uint16_t *begin, const uint16_t *end,
                  uint32_t *out_sum);
```

### 示例 1

```text
输入：a = [100,200,300,400], begin = a+1, end = a+3, out_sum = 123
输出：返回值 = 0, out_sum = 500
解释：只累加 200 和 300，end 指向的 400 不参与求和。
```

### 示例 2

```text
输入：begin = NULL, end = NULL, out_sum = 123
输出：返回值 = 0, out_sum = 0
解释：两个空端点约定为空范围，成功时输出总和 0。
```

### 示例 3

```text
输入：a = [100,200,300,400], begin = a+3, end = a+1, out_sum = 123
输出：返回值 = -1, out_sum = 123
解释：同一数组内，起始位置位于停止位置之后，区间非法。
```

### 提示与约束

- 每个输入元素的范围为 `[0,65535]`；总和等于 UINT32_MAX 时仍合法，超过才返回 `-2`。
- 调用者保证两个非 NULL 端点属于同一数组中的元素或其尾后位置；out_sum 指向独立可写对象，不与输入范围重叠。
- 判定优先级：out_sum 为 NULL → `-1`；仅一个端点为 NULL → `-1`；两端都为 NULL → 成功输出 0；再处理同数组内的反向、空范围、求和和溢出。
- 两个非 NULL 端点相等表示空范围，包括两者都在数组尾后位置；成功输出 0，不读取输入元素。
- 不解引用 end，不改输入数组，不依赖溢出后回绕的结果判断总和是否合法。
- 来自独立数组或悬空地址的端点违反调用前提，不要求函数检测，不应作为“必须拒绝”的运行测试；不能把任意两个指针先比较大小或相减来判断是否有效。

### 补充测试

使用示例中的数组，且每次重新设 out_sum 初值为 123：完整范围 `[a,a+4)` 成功输出 1000；`[a+2,a+2)`、`[a+4,a+4)` 成功输出 0；只有一个端点为 NULL 返回 `-1` 且输出不变；out_sum 为 NULL 时始终返回 `-1`，包括两端均为 NULL。

宿主机附加溢出测试：65537 个值均为 65535 的元素，总和恰好为 UINT32_MAX，应成功；65538 个这样的元素应返回 `-2` 且输出不变。可以使用静态数组，避免将大数组放到 MCU 栈上。

## Q5. 填充传感器结构体

### 题目描述

给定传感器字段 `id`、`adc`、`millivolts`、`status`，将它们写入输出指针 `out` 指向的结构体。

typedef struct {

下方示例的结构体按 `{id,adc,millivolts,status}` 的顺序表示。

- 用 `out->成员` 写入四个字段，不依赖结构体大小、对齐或填充字节。

## Q6. 写入大端 16 位整数

**难度：中等**　**标签：字节指针、字节序、缓冲区边界**　**答题文件：`q06.c`**

### 题目描述

给定字节缓冲区 `buffer`、可用字节数 `length`、从 0 计数的字节偏移 `offset` 和数值 `value`，将 value 编码为两个大端字节，写入 buffer 的 offset、offset+1 位置。

大端表示高 8 位在前，例如 `0x1234` 编码为 `0x12,0x34`。

成功返回 `0`，只修改这两个字节；buffer 为 NULL 返回 `-1`；指定位置不足两字节返回 `-3`。失败时整个缓冲区保持原状。

### 函数签名

```c
int write_be16_at(uint8_t *buffer, size_t length, size_t offset,
                  uint16_t value);
```

### 示例 1

```text
输入：buffer = [0x55,0x55,0x55,0x55,0x55,0x55], length = 6, offset = 1, value = 0x1234
输出：返回值 = 0, buffer = [0x55,0x12,0x34,0x55,0x55,0x55]
解释：从字节偏移 1 开始写入高、低字节，其他位置保持不变。
```

### 示例 2

```text
输入：buffer = [0x55,0x55,0x55,0x55,0x55,0x55], length = 6, offset = 5, value = 0x1234
输出：返回值 = -3, buffer = [0x55,0x55,0x55,0x55,0x55,0x55]
解释：偏移 5 处只剩一个可用字节，不足以写入整个 16 位整数。
```

### 示例 3

```text
输入：buffer = NULL, length = 0, offset = 0, value = 0
输出：返回值 = -1
解释：本题的 buffer 必须非 NULL，length=0 不构成例外。
```

### 提示与约束

- length、offset 的类型为 `size_t`，单位都是字节；value 的类型为 `uint16_t`，全部取值均可编码，本题不使用 `-2`。
- 调用者保证 buffer 非 NULL 时至少有 length 个可访问字节；即使底层数组更大，也只能按 length 个字节可用处理。
- 检查优先级：buffer 为 NULL → `-1`；写入区间不在 `[0,length)` 内 → `-3`；否则成功。
- length 为 0、1，offset 等于或大于 length，或 offset 后只剩一个字节，都属于空间不足。
- 先确认范围合法再形成写入指针；不能因 `offset+2` 溢出回绕而错误放行，offset=SIZE_MAX 也必须安全拒绝。
- 用字节指针写入，不将 buffer 强转为 uint16_t 指针，不依赖宿主机字节序或非对齐访问能力。

### 补充测试

在 6 字节的缓冲区中验证：offset=0/value=0x0000；offset=0/value=0x1234；offset=4/value=0xFFFF 恰好写满；offset 分别为 6、7、SIZE_MAX 均返回 `-3`；length 分别为 0、1 时返回 `-3`。成功只改变指定两字节，失败时所有字节保持不变；同时检查两侧哨兵。

## 挑战. 编码固定长度传感器报文

**难度：中等**　**标签：结构体指针、序列化、错误处理**　**答题文件：`challenge.c`**

### 题目描述

给定只读传感器对象 `sensor`、可写缓冲区 `buffer`、容量 `capacity` 和输出长度指针 `out_written`，将传感器数据编码为固定 7 字节报文。

SensorData 定义与 Q5 相同，答题文件已提供。字段合法范围为 id `[1,3]`、adc `[0,4095]`、millivolts `[0,3300]`、status `[0,3]`；不检查 ADC 与毫伏值的换算关系。

报文不包含校验和，布局如下：

| 字节偏移 | 内容               |
| ---- | ---------------- |
| 0    | 固定帧头 0xAA        |
| 1    | id               |
| 2    | adc 高 8 位        |
| 3    | adc 低 8 位        |
| 4    | millivolts 高 8 位 |
| 5    | millivolts 低 8 位 |
| 6    | status           |

成功返回 `0`，只写入 7 字节，并设置 `*out_written=7`。任一指针为 NULL 返回 `-1`；字段非法返回 `-2`；字段有效但容量不足返回 `-3`。失败时缓冲区和输出长度均保持原状，源结构体始终不变。

### 函数签名

```c
int encode_sensor_frame(const SensorData *sensor, uint8_t *buffer,
                        size_t capacity, size_t *out_written);
```

示例的 sensor 按 `{id,adc,millivolts,status}` 表示；out_written 表示其指向的 size_t 对象当前的值。

### 示例 1

```text
输入：sensor = {2,2048,1650,1}, capacity = 8, out_written = 99,
      buffer = [0x55,0x55,0x55,0x55,0x55,0x55,0x55,0x55]
输出：返回值 = 0, out_written = 7,
      buffer = [0xAA,0x02,0x08,0x00,0x06,0x72,0x01,0x55]
解释：两个 16 位字段均以高字节在前编码，第八个字节不属于报文，保持原值。
```

### 示例 2

```text
输入：sensor = {2,2048,1650,1}, capacity = 6, out_written = 99,
      buffer = [0x55,0x55,0x55,0x55,0x55,0x55,0x55,0x55]
输出：返回值 = -3, out_written = 99,
      buffer = [0x55,0x55,0x55,0x55,0x55,0x55,0x55,0x55]
解释：本次仅允许使用 6 字节，放不下 7 字节报文，缓冲区和长度都不能改变。
```

### 示例 3

```text
输入：sensor = {2,4096,1650,1}, capacity = 6, out_written = 99,
      buffer = [0x55,0x55,0x55,0x55,0x55,0x55,0x55,0x55]
输出：返回值 = -2, out_written = 99,
      buffer = [0x55,0x55,0x55,0x55,0x55,0x55,0x55,0x55]
解释：字段范围错误优先于容量错误，因此返回 -2，且不修改输出。
```

### 提示与约束

- out_written 非 NULL 时指向一个可写的 `size_t` 对象；capacity 单位是字节。
- 调用者保证对象有效、容量真实，且源结构体、缓冲区、输出长度对象彼此不重叠。
- 检查优先级：三个指针 → 字段范围 → 容量；capacity=0 也不允许任何指针为 NULL。
- 返回值是状态码，实际报文长度通过 out_written 交付；失败时不能把输出长度擅自清零。
- 成功恰好写 7 字节，剩余字节不变；源结构体在成功、失败时均不得修改。
- 逐字段编码，不复制结构体原始内存，不依赖 sizeof(SensorData)、填充字节或 CPU 字节序。
- 本文件独立编译；如需辅助逻辑，在本文件自行编写，可用 static 函数，不链接带 main 的 q05.c、q06.c。

### 补充测试

所有报文字节以下均以十六进制表示：

| 场景                                               | 预期结果                              |
| ------------------------------------------------ | --------------------------------- |
| `{2,2048,1650,1}`，capacity=7                     | 成功，报文 `AA 02 08 00 06 72 01`，长度=7 |
| 最小字段 `{1,0,0,0}`，capacity=7                      | 成功，报文 `AA 01 00 00 00 00 00`，长度=7 |
| 最大字段 `{3,4095,3300,3}`，capacity=7                | 成功，报文 `AA 03 0F FF 0C E4 03`，长度=7 |
| 字段合法，capacity 分别为 0～6                            | 返回 `-3`，缓冲区与原长度不变                 |
| 分别只令 id=0、adc=4096、millivolts=3301、status=4，其余合法 | 返回 `-2`，缓冲区与原长度不变                 |
| 每次令一个指针为 NULL，其余有效；capacity=7 或 0                | 返回 `-1`，不访问 NULL，其他输出保持原状         |
