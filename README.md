## 怎么做一道题

1. 阅读对应周的 `README.md`，例如 `week_002/README.md`。
2. 打开对应 `.c`，实现标有 `TODO` 的函数。
3. 在该文件的 `main()` 中写自己的测试，例如调用函数、打印结果或使用 `assert()`。
4. 编译、运行，检查是否符合题目给出的预期。

框架中的 `return -99;` 只是占位，需要你替换。`main()` 当前只打印“尚未完成”，不是测试。**编译成功不代表题目完成。**

## 编译与运行

你的电脑已有 GCC、GDB 和 `mingw32-make`。在 VS Code 中通过英文入口 `E:\Embedded-C-Practice` 打开本项目，兼容旧 GDB 的路径处理。

终端进入对应周目录，以下以第二周为例：

```powershell
cd 'E:\Embedded-C-Practice\week_002'
mingw32-make q02
.\q02.exe
```

或直接用 GCC：

```powershell
gcc -std=c11 -Wall -Wextra -Wpedantic -O0 -g q02.c -o q02.exe
.\q02.exe
```

每题独立编译：Q3 用 `mingw32-make q03`，挑战用 `mingw32-make challenge`。`mingw32-make all` 编译全部七题。生成的 `.exe` 就在对应 `.c` 旁边，不需要你编辑。

在 VS Code 打开某个 `.c` 后，按 `Ctrl+Shift+B` 编译；F5 使用 GDB 调试，需安装微软 C/C++ 扩展。编译配置中的 MinGW 标准 I/O 宏用于支持 `%zu`、`%td` 等标准 C 格式。

各题都有自己的 `main()`，不要把所有 `.c` 链接成一个程序。当前框架没有外部测试文件、公共头文件或 Python 构建脚本。
